# SMDPIS — Social Media Data Parser & Intelligence System

SMDPIS ingests social-media datasets (CSV / JSON / JSONL / Parquet), parses and preprocesses them, trains scikit-learn models, visualizes interaction networks, and produces court-style evidence packages with a verifiable chain of custody.

It is a **working system**, not a mockup: every number shown in the dashboard is computed by the backend from real data and real model artifacts. No metrics are hardcoded in the frontend.

## 1. Ethics, licensing and data provenance

- **Public, authorized sources only — never authenticated scraping.** SMDPIS contacts only sources that publish unauthenticated read endpoints or that explicitly permit automated access. It never logs in, never bypasses access controls, never stores credentials, and never renders JavaScript to get around a site's protections. Uploaded files and the bundled synthetic sample remain fully supported, and `SMDPIS_FETCH_ENABLED=false` disables *all* outbound traffic while leaving uploads untouched.
- **Every outbound request is guarded.** `http(s)` only, no embedded URL credentials, every DNS answer must be a public address (re-checked after **each** redirect, so a `302` to `169.254.169.254` is refused rather than followed), optional host allow-list, size and timeout caps, a per-host politeness delay, and `robots.txt` honoured unless `SMDPIS_ROBOTS_OBEY=false`.
- **Blanket-blocked platforms fast-fail with an explanation.** X, Reddit, LinkedIn, Facebook, Instagram and Threads publish blanket prohibitions on automated access (and reject non-browser clients beyond robots.txt), so requests to them fail immediately — before any DNS lookup or robots round-trip — with the platform's own stated rules and what to do instead (`/api/datasets/sources` → `policy.blocked_domains` lists them).
- **Synthetic sample data.** `data/sample/smdp_posts.csv` is generated by `scripts/generate_sample_data.py` — 10,000 post-level records across 1,000 accounts on 5 platforms (`x`, `reddit`, `mastodon`, `threads`, `youtube`). All accounts, texts, domains (reserved `.example` TLD) and engagement figures are invented. No real person, organization or event is represented.
- **Source terms still apply.** Availability of the two unauthenticated connectors (Mastodon tag API, Bluesky public appview) depends on each source's own rate limits and any CDN/WAF in front of it. SMDPIS reports the status code it received as `422` rather than working around a block. Reddit is not offered: its public JSON API was withdrawn in 2023 (`403` to scripts, `robots.txt` now `Disallow: /`) and official access needs an OAuth user login, which SMDPIS never performs or stores.
- **No private data.** Uploaded or collected files are processed locally; IP addresses are redacted automatically at ingestion (`[REDACTED]`).
- **Terminology.** Automation scoring is reported as **"Automated-account likelihood"** and label outputs as **"Model classification"** — these are model outputs, not determinations about real people. Every ML panel carries a disclaimer.
- **No model → no number.** If no ACTIVE model exists for a task, the API returns `409 model_not_trained` and the UI shows "Model not trained" instead of a fabricated value.
- **Dataset licensing.** The bundled sample is released with this repository under the same license as the code (synthetic data, no third-party content). If you upload public datasets, you are responsible for confirming their license permits your use; record provenance in `backend/datasets/dataset_catalog.json`.


## 3. Features

- **Web collection** — fetch a public file, collect via official platform APIs (Mastodon, Bluesky), or crawl a site's public pages through SSRF-guarded requests with robots.txt respect, byte/timeout caps and full chain-of-custody logging.
- **Dataset catalog** — upload CSV/JSON/JSONL/Parquet, list, profile (schema, dtypes, nulls, unique users, platforms), row query with search/pagination, soft delete, version lineage.
- **Preprocessing** — text cleaning (lowercase, URL/mention/hashtag handling, tokenization), missing-value handling, dedup, label derivation; creates a *new* dataset version linked to its parent.
- **Sentiment** — VADER lexicon scoring with per-post labels and a daily timeline.
- **Topics** — TF-IDF + NMF topic modeling; topic count follows the ACTIVE topic model (`k`), with top terms and distribution.
- **Automated-account likelihood** — 10 account-level features (followers, following, post count, posting frequency, avg interval, avg text length, dup content ratio, engagement ratio, activity regularity, account age) → trained classifier → per-account score + risk band. Requires an ACTIVE model (else 409).
- **Misinformation classification** — content-level model classification with confidence, limited to 500 rows by default.
- **Network graph** — D3 force-directed view of account interactions with node sizing by degree and community detection (networkx).
- **Evidence chain of custody** — immutable raw file, SHA-256 content hash, HMAC-SHA256-signed audit events, `EV-YYYYMMDD-XXXXXX` identifiers, verification endpoint.
- **Reports** — assemble dataset + analysis + evidence + model metrics into a downloadable report.
- **Model registry** — one ACTIVE model per task, activate/archive, training jobs with progress, real evaluation metrics only.
- **Dashboard** — record/account counts, platform distribution, activity timeline, sentiment timeline, automated-account likelihood summary, flagged-content summary, topic count, active-model accuracies, warnings when something is unavailable.

## 5. Quick start (local, SQLite)

Open a terminal in the repository root (`HawkEYE/`).

### 5.1 Backend

```powershell
# create virtualenv (first run only)
python -m venv .venv

# install dependencies (first run only)
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt

# start the API (auto-bootstraps sample data + 4 models on first run)
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

On first start the backend runs **bootstrap** (`SMDPIS_AUTO_BOOTSTRAP=true`): it generates the 10,000-row sample dataset, ingests it, and trains + activates all four baseline models. Watch the log lines `Bootstrap: trained and activated MDL-...`; once complete, `/api/health` reports `bootstrap.status: "READY"`. Expect ~30–60 s.

Verify:

```powershell
Invoke-RestMethod http://127.0.0.1:8000/api/health
```

### 5.2 Frontend

In a second terminal:

```powershell
cd frontend
npm install        # first run only
npm run dev
```

Open <http://localhost:5173>. The Vite dev server proxies `/api` to `http://127.0.0.1:8000`.

## 9. ML tasks and models

| Task | Script | Default model | Key metrics |
|------|--------|---------------|-------------|
| `sentiment` | `ml/training/train_sentiment.py` | LogisticRegression on TF-IDF | accuracy ≈ 0.90, F1, ROC-AUC |
| `bot_detection` | `ml/training/train_bot_detection.py` | LogisticRegression on 10 account features | accuracy, F1, ROC-AUC (needs ≥ 40 accounts) |
| `misinformation` | `ml/training/train_misinformation.py` | LinearSVC + calibration on TF-IDF | accuracy, F1, ROC-AUC |
| `topic_model` | `ml/training/train_topics.py` | TF-IDF + NMF, `k` topics | coherence-style metrics, `n_topics` |

Identifiers: `MDL-SENT-001`, `MDL-BOT-001`, `MDL-MIS-001`, `MDL-TOP-001`. Exactly **one ACTIVE model per task**; artifacts are stored under `backend/models/<task>/` and loaded on demand. Metrics come from held-out evaluation performed during training — nothing is hardcoded.

Training pipeline: load → validate schema → preprocess → train/test split → fit → evaluate (confusion matrix + per-class metrics) → save metrics + model → register + activate.

## 10. Evidence chain of custody

1. **Ingestion** writes an immutable copy of the uploaded file to `data/raw/` and records its **SHA-256**.
2. An **evidence item** is created with ID `EV-YYYYMMDD-XXXXXX` and a content hash.
3. Every meaningful action (ingest, preprocess, analyze, train, report) appends an **audit event** signed with **HMAC-SHA256** using `SMDPIS_SECRET_KEY`.
4. Derived data (parquet under `data/processed/`) is always *separate* from the raw evidence — raw bytes are never rewritten.
5. `GET /api/evidence/{id}/verify` re-hashes the stored file and validates the audit chain, returning `valid: true/false`.

Datasets are **soft-deleted** (status change, rows retained) so the chain stays intact.

## 13. Project workflow

1. **Discover** — browse the catalog, fetch/collect/crawl from a public source, or upload your own file.
2. **Ingest** — raw copy + hash + evidence ID created; column mapping auto-detected.
3. **Profile** — inspect schema, nulls, unique users, platform spread.
4. **Preprocess** — clean text, handle missing values, derive labels → new dataset version.
5. **Train** — run one or all four trainers (CLI or `POST /api/ml/train`).
6. **Analyze** — sentiment, topics, automated-account likelihood, misinformation.
7. **Explore** — row explorer, charts, D3 network graph.
8. **Preserve** — review evidence items and verify the audit chain.
9. **Report** — generate a report bundling data + analysis + model metrics + evidence.

## 14. Limitations and responsible use

- Models are trained on **synthetic** data and are demonstration-grade; do not use their outputs to accuse, de-platform, or profile real individuals.
- "Automated-account likelihood" is a **statistical score**, not proof of automation; "Model classification" is a prediction, not a fact.
- VADER sentiment and NMF topics are lexicon/frequency heuristics — sarcasm, code-switching and domain jargon degrade quality.
- The network graph uses interactions *present in the uploaded dataset*; it is not a map of an entire platform.
- Misinformation detection is a classifier over patterns in text; it cannot establish truth.
- No authentication/authorization layer is included — deploy behind a reverse proxy with auth, and set a strong `SMDPIS_SECRET_KEY`.
- Keep uploads free of personal data; IP redaction is automatic but other PII in free text is your responsibility.
- Web-collection connectors depend on each source's availability: their rate limits, and any CDN/WAF in front of them, can reject a request at any time. SMDPIS surfaces the source's status as `422` rather than retrying around a block, so a collection may simply fail until the source allows it again.

## 15. Security notes

- Secrets come from the environment only; `.env` is git-ignored, `.env.example` holds placeholders.
- Audit records are HMAC-SHA256 signed; tampering breaks verification.
- Uploads are validated by extension and size (`SMDPIS_MAX_UPLOAD_MB`), and stored outside the web root.
- Raw evidence is write-once; derived artifacts are separate files.
- The Docker backend runs as a non-root user.
- CORS is restricted to the configured origins.
- All outbound collection goes through an SSRF guard: `http(s)` scheme only, URL-embedded credentials refused, every DNS answer must be a public IP (re-validated after each redirect), optional `SMDPIS_FETCH_HOST_ALLOWLIST`, byte and timeout caps, per-host politeness delay, and `robots.txt` honoured unless `SMDPIS_ROBOTS_OBEY=false`. Known blanket-blocked platforms (X, Reddit, LinkedIn, Facebook, Instagram, Threads) fast-fail before any network I/O with an explanation. Set `SMDPIS_FETCH_ENABLED=false` to disable outbound requests entirely.
- Error handlers never leak stack traces to clients (500s log details server-side).
